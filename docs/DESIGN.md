# 设计说明 · 大家来决定

## 1. 概念

**一间线上的公共议事厅。** 视觉语言来自投票纸、票根和公告栏：暖纸底色、墨黑衬线标题、朱红印章色、虚线撕口和半调网点。它要看起来可信、有人味，而不是又一个紫色渐变的 SaaS。

关键词：纸感、克制、可读、轻微的印刷错位感。

## 2. 设计工程化方法

| 方法 | 落地 |
|---|---|
| Design tokens | `styles/tokens.css` 单一来源；组件不写魔法值 |
| Atomic Design | primitives（Button/Field/Avatar/Modal/Toast）→ molecules（VoteBox/QuestionCard/PublishModal）→ pages |
| API-first | 先定 `docs/API.md` 与 `api/types.ts`，前后端按契约并行 |
| 状态机 | 认证 `loading/anon/authed`；投票 `idle/editing/submitting/voted/error` |
| 乐观更新 | 投票先改本地计数与进度条，失败用旧 question 回滚并 toast |
| 渐进增强 | 原生 `form/button/dialog`，无自定义 div 按钮；语义与键盘完整 |
| 响应式 | 移动优先，断点 520 / 760 / 900 / 1080；内容最大宽 1180 |
| 可访问性 | label 关联、`aria-invalid`、`aria-live` toast、dialog 焦点陷阱、`prefers-reduced-motion` |
| 视觉回归 | `tests/capture.py` 用 Edge 无头截取 6 张关键页 |
| DoD | 构建通过 + API 测试 + E2E + 截图才算完成 |

## 4. 页面规格

### 登录 `/login`
- 桌面 46/54 分栏：左侧墨色品牌区（Logo、主张、3 张倾斜票根、总量统计），右侧纸色表单。
- 表单：登录/注册双 Tab；登录字段「用户名或邮箱 + 密码」，注册「昵称 + 邮箱 + 密码 + 确认」。
- 状态：行内校验（提交时）、字段级服务端错误、顶部 Alert（非字段错误）、提交 loading、密码可见切换、体验账号一键登录。
- ≤900px：品牌区压缩为顶部介绍（隐藏票根），表单全宽；≤520px：隐藏 Logo 文字。
- 成功后跳转 `next`（仅允许站内路径），未登录投票会带 `next` 回到原页。
- 注册成功且邮箱未验证时进入 `/verify-email?status=sent`，而不是直接回广场。
- 密码下方提供「忘记密码？」；连续失败被锁定时用顶部 Alert 显示 429 提示；重置成功回到登录页显示绿色成功提示。

### 找回密码 `/forgot-password`
- 居中恢复卡片，说明“无论邮箱是否存在都显示相同结果”。
- 提交后展示统一成功态：检查收件箱、链接 30 分钟有效；开发环境显示 `/dev/mail` 入口。
- 可返回登录或换一个邮箱重填。

### 重置密码 `/reset-password`
- 从邮件链接进入，展示新密码 + 确认密码表单。
- 成功后吊销全部会话并回到登录页，顶部显示「密码已重置，请用新密码登录」。
- 缺少 token、过期或已使用时展示无效态，引导重新申请。

### 邮箱验证 `/verify-email`
- 与品牌一致的居中卡片：顶部虚线印章条、状态图标、标题、说明、操作区。
- `sent`：验证邮件已发送；提供重发、账号设置、先逛逛；开发环境显示 `/dev/mail` 入口。
- `success`：验证成功；已登录显示「去发起投票」，未登录显示「去登录」。
- `expired / used / invalid / send-failed`：链接失效或邮件未发出说明；已登录可重发，未登录引导登录。
- 未验证用户在所有页面看到顶部窄横幅「邮箱未验证…」；`/settings#email` 是修复入口。

### 账号设置 `/settings`
- 左侧账号卡 + 锚点导航（账号信息 / 邮箱验证 / 登录与安全 / 危险区）；≤900px 折叠为横向导航。
- 邮箱验证区块：未验证显示邮箱、原因说明、重发按钮（60 秒倒计时）与开发邮件箱入口；已验证显示绿色标签与验证时间。
- 账号信息：头像、昵称、邮箱、加入时间、身份标签；昵称与邮箱暂为只读。
- 登录与安全：改密表单；设备列表展示浏览器·系统、IP、最近活动、登录时间与有效期，当前设备高亮，可单设备退出或一键退出其他设备。
- 危险区：红色警示卡 + 原生 `<dialog>` 二次确认；要求当前密码并输入「注销」，说明内容保留与匿名化规则。

### 开发邮件箱 `/dev/mail`
- 仅开发环境；列表展示收件人、主题、正文、发送/过期时间。
- 按 `kind` 标记「验证邮箱 / 重置密码」，按钮分别为「打开验证链接 / 打开重置链接」。
- 作为 console transport 的可视化替身；生产环境 API 返回 404，页面显示未启用说明；不加入主导航。

### 首页 `/`
- 顶栏：Logo、广场/我的、搜索、发起投票、头像菜单。
- Hero：主张 + 发布入口（虚线卡片，像一张待填的选票）。
- 工具栏：搜索、排序（热门/最新/最有争议/即将截止）、分类 Chip。
- 信息流卡片：作者、时间、分类、状态、标题、说明、投票区、理由数。
- 右栏：今日热议、玩法说明、印章装饰；≤1080px 隐藏。
- 状态：骨架屏、空态、错误重试、加载更多、到底提示。

### 投票
- 未投票：只显示「已有 N 人投票」，不显示比例（减少从众）；可「先看结果」。
- 点击是/否：未登录 → 登录；已登录 → 原位展开理由（≤200 字）+ 匿名 + 提交。
- 已投票：显示比例、自己的选择、改票；截止后禁用投票并展示最终结果。
- 乐观更新 + 失败回滚。

### 发布（弹窗）
- 标题（4–80）、说明（≤500）、分类、截止（24h/3天/7天/不设）、匿名。
- 实时预览卡片；提交后跳详情；未登录自动去登录并回填 `?compose=1`。

### 详情 `/q/:id`
- 标签、标题、说明、作者/匿名、时间、参与人数。
- 大投票区；右侧「LIVE TALLY」票数卡（深色）、发起人、复制链接。
- 理由列表：全部/是/否筛选；自己的理由即时置顶。
- ≤1080px：侧栏下移为两列，再窄为单列。
- 已注销作者在卡片、详情、理由中统一显示「已注销用户」，详情侧栏标注「账号已注销，内容保留」。

### 我的 `/me`
- 我发起的 / 我参与的；空态引导；卡片紧凑模式。

### 管理台 `/admin`
- 只有 `role=admin` 可见；普通用户访问显示 403 引导，未登录跳登录并回跳。
- 左侧固定导航：概览 / 内容管理 / 用户管理；≤980px 变为横向导航。
- 概览：四个统计卡（用户/问题/投票/理由）、今日增量、分类分布条、最新问题。
- 内容管理：标题/作者搜索、状态筛选、分页表格；行内「精选 / 截止 / 重开 / 删除」。
- 用户管理：昵称/邮箱搜索；展示角色、状态、发起/投票数与注册时间；未验证账号在邮箱旁标记「未验证」；「停用 / 恢复」；已注销账号只读。
- 危险操作（删除、停用）二次确认；操作结果用 Toast 反馈，不整页刷新。

## 5. 无障碍

- 所有输入有可见 label；错误用 `aria-invalid` + `aria-describedby`。
- 弹窗使用原生 `<dialog>`，自带焦点陷阱与 Esc；关闭按钮有 `aria-label`。
- Toast `aria-live="polite"`；投票结果条提供 `role="img"` 文本替代。
- 触控目标 ≥ 44px（按钮 46、投票 46、菜单 34 但外层有间距）。
- 焦点环 3px 蓝色，不被 `outline: none` 移除。
- 尊重 `prefers-reduced-motion`，关闭所有动画与平滑滚动。

## 6. 关键决策

1. **结果延迟可见**：投票后才显示比例，减少从众效应；「先看结果」保留自由度。
2. **理由可选**：降低投票门槛，但结果页突出理由，鼓励表达。
3. **匿名是发布/投票的属性**：不引入复杂隐私模型；服务端对匿名作者/投票者隐藏身份。
4. **不做评论树**：核心是「一票一理由」，保持信息密度与阅读节奏。
5. **不用组件库**：为品牌感与体积可控，手写 primitives；代价是更多 CSS 维护。
6. **验证链接直接 GET**：邮箱里点开即完成验证，再 303 到结果页；token 一次性、24 小时有效、只存 hash。开发环境用 `/dev/mail` 替代真实收件箱。
7. **找回密码统一回应**：无论邮箱是否存在都返回相同结果，避免枚举；重置 token 30 分钟、一次性，成功后吊销全部会话并解锁账号。
